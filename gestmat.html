Contexte

GestMat est une application web de gestion de parc informatique développée en PHP/MySQL dans le cadre de mon BTS SIO SLAM à l'INSTA Paris. L'objectif pédagogique était de concevoir une application multi-pages complète reposant sur une base de données relationnelle, avec une logique métier robuste et une interface responsive.

Le projet simule un système réel de prêt de matériel au sein d'un établissement scolaire ou d'une entreprise : chaque équipement peut être emprunté par un utilisateur pour une durée définie, puis restitué. L'application suit en temps réel l'état du parc et déclenche des alertes visuelles automatiques lorsqu'un matériel n'a pas été rendu à temps.

L'accent a été mis sur la cohérence des données via les transactions SQL (BEGIN / COMMIT / ROLLBACK) et la sécurité via PDO avec requêtes préparées — zéro concaténation directe de variables SQL.

03

Fonctionnalités réalisées

—
Tableau de bord avec KPIs en temps réel
4 compteurs calculés dynamiquement à chaque chargement : Total du parc, Disponibles, Empruntés, En retard. La logique repose sur une requête SQL avec LEFT JOIN entre les tables materiels et emprunts.
—
CRUD complet — Inventaire & Emprunts
Gestion complète de l'inventaire (8 équipements de démonstration), enregistrement d'un emprunt (formulaire validé côté serveur) et restitution d'un matériel. Chaque opération met à jour en cohérence les deux tables de la base.
—
Transactions SQL atomiques
Chaque emprunt et chaque retour sont effectués en transaction : si l'une des 2 requêtes échoue (INSERT + UPDATE ou UPDATE + UPDATE), un ROLLBACK annule l'ensemble — aucun état intermédiaire incohérent n'est possible.
—
Alertes automatiques de retard
Chaque ligne du tableau est comparée à la date du jour via l'objet PHP DateTime. Si la date de retour prévue est dépassée et le matériel toujours emprunté, la ligne passe en rouge et affiche le nombre de jours de retard.
—
Interface responsive Bootstrap 5
Tableau de bord avec cartes KPI, tableau interactif avec badges de statut colorés, formulaire d'emprunt avec validation HTML5 et affichage d'erreurs serveur. Colonnes secondaires masquées automatiquement sur mobile.
04

Architecture MVC légère

Le projet adopte une architecture MVC simplifiée, sans framework, pour séparer clairement les responsabilités :

config.php
Connexion PDO centralisée via pattern Singleton léger. Constantes de connexion, options PDO (exceptions, fetch associatif, vraies requêtes préparées).
index.php
Vue principale : inventaire complet avec LEFT JOIN, calcul des KPIs, détection des retards et affichage des messages flash (succès/erreur).
emprunter.php
Contrôleur + Vue : vérification de disponibilité, validation du formulaire côté serveur, transaction SQL (INSERT emprunts + UPDATE materiels).
rendre.php
Contrôleur pur (pas d'interface) : vérification de l'emprunt, transaction SQL (UPDATE emprunts rendu='oui' + UPDATE materiels statut='disponible'), redirection.
05

Sécurité & Bonnes pratiques

01
Requêtes préparées PDO
Toutes les requêtes SQL utilisent PDO avec paramètres liés (execute([':param' => $val])). Aucune concaténation directe — protection totale contre les injections SQL.
02
Transactions atomiques
BEGIN / COMMIT / ROLLBACK garantissent qu'aucune opération partielle ne peut corrompre la base. Si l'une des requêtes échoue, tout est annulé.
03
Validation serveur & XSS
Toutes les entrées utilisateur sont validées côté serveur (longueur, format de date) avant traitement. L'affichage passe systématiquement par htmlspecialchars().
04
Cast sécurisé des IDs
Les identifiants reçus en GET sont systématiquement castés en (int), empêchant toute manipulation de l'URL par injection de chaînes.
