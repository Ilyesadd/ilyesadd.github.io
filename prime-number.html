01

Contexte

Prime Number est un projet console Java développé dans le cadre du BTS SIO SLAM. L'objectif pédagogique était de mettre en pratique les fondamentaux du langage Java : programmation orientée objet, gestion des exceptions et optimisation algorithmique — sans dépendance externe, uniquement la bibliothèque standard.

Le programme permet à l'utilisateur de tester si un entier est premier, d'en obtenir la liste des diviseurs, et de quitter proprement via un menu do…while. L'accent est mis sur la séparation des responsabilités entre les classes et sur la robustesse face aux saisies invalides — deux points essentiels à valoriser à l'oral du BTS.

Points clés techniques

—
Encapsulation & séparation des responsabilités
Le projet est découpé en trois classes distinctes : Calculateur contient la logique algorithmique (estPremier, getDiviseurs) sans aucune notion d'affichage ; Affichage gère l'interface console sans connaître les calculs ; Main orchestre le tout. Chaque classe fait une seule chose — principe de responsabilité unique.
// Calculateur.java — aucune dépendance vers l'UI
public class Calculateur {
  public boolean estPremier(int n) { ... }
  public List<Integer> getDiviseurs(int n) { ... }
}
—
Optimisation O(√n) avec Math.sqrt
Pour tester la primalité, il suffit de chercher un diviseur jusqu'à √n. Raisonnement : si n = a × b avec a ≤ b, alors a ≤ √n — inutile d'aller plus loin. Cette optimisation réduit la complexité de O(n) à O(√n), ce qui est décisif pour de grands entiers.
public boolean estPremier(int n) {
  if (n < 2) return false;
  for (int i = 2; i <= Math.sqrt(n); i++) {
    if (n % i == 0) return false;
  }
  return true;
}
—
Boucle do…while — menu persistant
Contrairement à une boucle while classique, le do…while garantit que le corps s'exécute au moins une fois — l'utilisateur voit toujours le menu au démarrage. L'utilisateur tape 0 pour sortir proprement via un break.
do {
  afficherMenu();
  int choix = scanner.nextInt();
  if (choix == 0) break;
  traiterChoix(choix);
} while (true);
—
Gestion d'erreur try/catch — piège du buffer Scanner
Si l'utilisateur saisit un texte non-entier, un InputMismatchException est levé. Sans appel à scanner.nextLine() dans le catch, le texte invalide reste dans le buffer et la boucle tourne à l'infini — un piège classique à mentionner à l'oral.
try {
  int n = scanner.nextInt();
  traiter(n);
} catch (InputMismatchException e) {
  scanner.nextLine(); // ← vider le buffer !
  System.out.println("Entrée invalide.");
}
—
Bonus technique — getDiviseurs() avec ArrayList & Collections.sort()
La méthode retourne une List<Integer> construite avec un ArrayList, puis triée avec Collections.sort(). Le même principe √n est appliqué : on ajoute i et n/i en une seule passe pour éviter les doublons et réduire la boucle à O(√n).
public List<Integer> getDiviseurs(int n) {
  List<Integer> divs = new ArrayList<>();
  for (int i = 1; i <= Math.sqrt(n); i++) {
    if (n % i == 0) {
      divs.add(i);
      if (i != n / i) divs.add(n / i); // évite le doublon
    }
  }
  Collections.sort(divs);
  return divs;
}

Structure du projet

Main.java
Point d'entrée — orchestre le menu do…while, instancie Calculateur et Affichage, délègue le traitement sans connaître les détails d'implémentation.
Calculateur.java
Logique pure : estPremier(n) et getDiviseurs(n). Aucune référence à Scanner ou System.out — testable indépendamment et réutilisable.
Affichage.java
Couche présentation : affiche le menu, formate les résultats, gère les messages d'erreur. Ne fait aucun calcul — reçoit les résultats de Calculateur.
README.md
Documentation du projet : explication des algorithmes, instructions de compilation et d'exécution, exemples de sorties attendues.
